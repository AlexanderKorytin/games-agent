# План: Nintendo eShop рядом со Steam

Дизайн: `docs/игровой-агент.md`, раздел «Пятый заход Research (2026-10-19)». Решения
пользователя: регион США, игра в обоих магазинах — одна плашка, один вкус, оценка Steam → иначе
Metacritic, 10 игр всего, сайты через MCP, форумы не делаем.

## Уточнения дизайна, принятые при разведке кода

- **Номер игры eShop — nsuid, целое число в той же колонке `номер`.** Замер: nsuid — 14 цифр,
  начало `7001…` (`70010000130792`), номер Steam — до 8 цифр. Граница `НАЧАЛО_НОМЕРОВ =
  70_000_000_000_000` разводит магазины без перестройки ключей таблиц. Запрет
  `Не предлагать: «…» (70010000130792)` разбирается нынешним `taste._ЗАПРЕТ` без правки.
- **Сервер MCP не переименовывается.** Имя `steam` вшито в разрешения (`mcp__steam__*`),
  профиль советника и историю разговора; новое имя ничего не даёт.
- **Инструмент `eshop_game` не нужен.** `eshop_find` сразу отдаёт полные записи каталога (имя,
  платформы, дата, цена, жанры, описание, ссылка): каталог Algolia возвращает их одним запросом.
- **Пара «та же игра в Steam» живёт в таблице `pairs`.** Плашка пары — по номеру Steam; игра
  eShop без пары — по nsuid. Источник eShop в заданиях даёт только игры **без** пары в Steam:
  игры с парой приходят через поиск Steam и получают цену eShop привязкой.
- **Оценка eShop-игры — оценка игроков Metacritic**, хранится в тех же полях `отзывы_*`.
  Сводка — без слова «Metacritic»: источник следует из магазина плашки (игра без пары в Steam —
  всегда Metacritic).
- **Предел каталога, названный вслух.** Algolia отдаёт не больше 1000 записей на запрос
  (замер: 20 страниц по 50, страница 20 пуста). Это предел магазина, не наш: глубже 1000
  популярных вышедших игр источник eShop не идёт. Для игр без пары в Steam (в основном игры
  Nintendo и эксклюзивы) этого хватает.
- **Цена запроса недели.** Страница eShop — 50 записей: на каждую без сведений о паре — один
  поиск Steam, затем на каждую без пары — два запроса Metacritic. Первая неделя — до 150
  запросов, порядка 1–3 минут; дальше пары берутся из `pairs`.

## Тесты

Правило проекта: проверки без сети и ключа, на образцах настоящих ответов. Деление:

- **Логика и границы данных** (разбор ответов, хранилище, переход схемы, задания, `.ics`) —
  строгий цикл: тест, убедиться, что падает, код, убедиться, что проходит.
- **Страница** (`index.html`) — ручной прогон по сценарию из шага: оформление дешевле проверить
  глазами, чем описывать проверкой.

## Шаг 1. Снять образцы ответов eShop и Metacritic

**Файлы**: `mcp_servers/steam/образцы/` — новые файлы ниже.
**Зачем**: проверки без сети на настоящих ответах (правило проекта).
**Проверка**: файлы есть, каждый — валидный JSON (HTML — для страницы товара), размер каждого
меньше 50 КБ.
**Содержание**: скрипт в каталоге черновиков сессии, не в проекте. Ответы урезаются до нужного:
- `eshop_upcoming.json` — `POST КАТАЛОГ/query`, `filters: topLevelCategory:"Games" AND
  (availability:"Coming soon" OR availability:"Pre-order")`, `hitsPerPage: 400`; из `hits`
  оставить 4 записи: одну с точной датой (`releaseDateDisplay: null`), одну с `releaseDateDisplay:
  "2027"`, одну с `dlcType: "Individual"`, одну с `isUpgrade: true` либо `topLevelFilters`
  с `"Upgrade pack"`.
- `eshop_object_70010000130792.json` — `GET КАТАЛОГ/7100130792`.
- `eshop_find_hollow_knight.json` — `query: "Hollow Knight"`, `hitsPerPage: 10`.
- `eshop_price_us.json` — `GET ЦЕНЫ?country=US&lang=en&ids=70010000000185,70010000117094`
  (первая — со скидкой и `end_datetime`, вторая — `not_found` в США; если на день съёмки
  скидки нет — подобрать nsuid со скидкой из `topLevelFilters:"Deals"`).
- `eshop_product.html` — страница `САЙТ/us/store/products/nintendo-switch-sports-resort-switch-2/`,
  урезанная до одного тега `<script id="__NEXT_DATA__" type="application/json">` с JSON, где
  в `props.pageProps.initialApolloState` оставлен только ключ `Product:{"sku":"7100125145"}`.
- `metacritic_search_bananza.json` — `GET АДРЕС/finder/metacritic/search/donkey kong bananza/web?mcoTypeId=13&limit=5`.
- `metacritic_user_bananza.json` — `GET АДРЕС/reviews/metacritic/user/games/donkey-kong-bananza/stats/web?platform=nintendo-switch-2`.
- `steam_storesearch_hollow_knight_en.json` — `GET store.steampowered.com/api/storesearch/?term=Hollow Knight&l=english&cc=ru`.

## Шаг 4. `это_eshop`, `чистое_имя`, `сравнимое`

**Файлы**: `mcp_servers/steam/eshop_store.py` (новый), `tests/test_eshop.py` (новый)
**Зачем**: развести магазины по номеру; сравнивать имена двух магазинов.
**Проверка**: тесты:
- `это_eshop(70010000130792)` — истина; `это_eshop(1086940)` — ложь;
- `сравнимое("Hollow Knight – Nintendo Switch 2 Edition") == сравнимое("Hollow Knight")`;
- `сравнимое("Pokémon™ Legends: Arceus") == "pokemon legends arceus"`;
- `сравнимое("Super Mario Galaxy™ + Super Mario Galaxy™ 2") != сравнимое("Super Mario Galaxy™ 2")`;
- `чистое_имя("The Legend of Zelda™: Tears of the Kingdom – Nintendo Switch™ 2 Edition") ==
  "The Legend of Zelda: Tears of the Kingdom"`.
**Содержание**: шапка модуля — что это не открытый API (Algolia сайта, `api.ec`, страница
товара), регион США, состояния нет. `чистое_имя`: убрать `™®©`; убрать хвост
`r"\s*[-–—:]?\s*Nintendo Switch(?:\s*2)?\s*Edition\s*$"` (без учёта регистра); сжать пробелы.
`сравнимое`: `unicodedata.normalize("NFKD")`, выбросить знаки категории `Mn`, `casefold`,
`re.sub(r"[^a-z0-9]+", " ", …).strip()`.

## Шаг 5. Разбор записи и выдачи каталога

**Файлы**: `eshop_store.py`, `tests/test_eshop.py`
**Зачем**: игры eShop в общем виде `Игра`.
**Проверка**: на `eshop_upcoming.json`: `разобрать_выдачу` отдаёт 2 игры (дополнение и пакет
обновления выброшены); у игры с точной датой `дата == date(…)`, `дата_текст` — она же в виде
`ГГГГ-ММ-ДД`, `вышла is False`; у игры с `releaseDateDisplay: "2027"` — `дата is None`,
`дата_текст == "2027"`; `цена` — центы (`59.99` → `5999`), `валюта == "USD"`; `адрес`
начинается с `https://www.nintendo.com/us/store/products/`; `обложка` начинается с `ОБЛОЖКИ`;
`объект` — `objectID`; `платформы` — `corePlatforms`. На `eshop_object_70010000130792.json`
`разобрать_запись` даёт `номер == 70010000130792`. Ответ без `hits` — `ss.ОшибкаМагазина`.
**Содержание**: `разобрать_запись(з)`: `None`, если `з["dlcType"]` не пусто, или `"Upgrade
pack"` в `topLevelFilters`, или `isUpgrade` истинно, или `nsuid` не строка цифр.
`вышла = not ({"Coming soon", "Pre-order"} & set(з.get("availability") or []))`.
`дата`: `releaseDateDisplay` не пусто → `None` и `дата_текст = releaseDateDisplay`; иначе
`date.fromisoformat(releaseDate[:10])`, `дата_текст = releaseDate[:10]`; нет `releaseDate` →
`None`, `""`. Цена: `price.finalPrice`, `price.regPrice` → `round(x * 100)`; `скидка =
round(price.percentOff or 0)`; `finalPrice` нет → `цена = None`. `бесплатна = finalPrice == 0`.
`жанры = tuple(gameGenreLabels)`; `описание = description`; `обложка = ОБЛОЖКИ +
productImage`, если он есть.

## Шаг 6. Разбор цен `api.ec`

**Файлы**: `eshop_store.py`, `tests/test_eshop.py`
**Зачем**: скидки eShop со сроком конца.
**Проверка**: на `eshop_price_us.json`: одна `Цена` для номера со скидкой — `цена` и
`цена_без_скидки` в центах, `скидка` в процентах `round(100 * (1 - скидочная / обычная))`,
`до` — `end_datetime[:10]`; номер `not_found` в словаре отсутствует. Ответ с полем `error`
— `ss.ОшибкаМагазина` с его `message`.
**Содержание**: `sales_status` `onsale` или `preorder` с `regular_price` → цена; есть
`discount_price` → скидочная цена и `до`; иначе `скидка = 0`, `до = ""`. Числа — из
`raw_value`.

## Шаг 8. Сетевые функции `eshop_store`

**Файлы**: `eshop_store.py`, `tests/test_eshop.py`
**Зачем**: запросы с той же политикой повторов, что у Steam.
**Проверка**: тесты на `httpx2.MockTransport`:
- `витрина(к, будущие=True, страница=2)` шлёт `POST …/query` с `page: 2`, `hitsPerPage: 50` и
  фильтром будущих; `будущие=False` — фильтр `availability:"Available now"`;
- `цены(к, список из 120 номеров)` делает 3 запроса (50, 50, 20) и сливает словари;
- `запись(к, "0000000000")` при ответе 404 — `None`;
- 429 дважды, затем 200 — ответ разобран (паузы подменены нулём через `monkeypatch` на

**Содержание**: `клиент()` — `httpx2.AsyncClient(timeout=ss.ОЖИДАНИЕ, headers={"User-Agent":

— `query: название`, `hitsPerPage: 10`. `игра(к, объект)`: `запись`, затем `описание(к,
адрес)`; непустое полное описание заменяет короткое (`dataclasses.replace`).

## Шаг 10. Metacritic: разбор

**Файлы**: `mcp_servers/steam/metacritic.py` (новый), `tests/test_metacritic.py` (новый)
**Зачем**: оценка игр без пары в Steam.
**Проверка**:
- `разобрать_поиск(образец, "Donkey Kong Bananza") == ("donkey-kong-bananza", ("Nintendo
  Switch 2",))`; для «Donkey Kong Bananza: DK Island & Emerald Rush» из той же выдачи берётся

- `платформа(("PC", "Nintendo Switch", "Nintendo Switch 2"), switch2=True) == "nintendo-switch-2"`;

**Содержание**: совпадение имён — `eshop_store.сравнимое`. Слаг платформы — имя в нижнем
регистре, пробелы → `-`. Порядок предпочтения: платформа игры (`switch2`), затем другая

**Зачем**: одна плашка с двумя ценами; оценка с названным источником.
**Проверка** (ручной сценарий):
- игра пары: строка цен «Steam: 999 ₽ · eShop: −50 % · 19.99 USD до 5 ноября», ссылки «в
  Steam» и «в eShop»; нажатие на плашку — клиент Steam, как было;
- игра eShop без пары: обложка Nintendo, подпись «игроки Metacritic: в целом хорошие, 86 % из
  3 293», ссылка «в eShop»; нажатие открывает страницу eShop в новой вкладке;
- календарь: у игры eShop в клетке дня и в списке — пометка «Switch»;
- строка хода советника: `eshop_find` → «Ищу «…» в eShop».
**Содержание**: `обложка(и)`: адрес Steam по номеру — только для `и.магазин === "steam"`;
`цена(и)` + `цена_пары(и)`; подпись оценки по `и.магазин`; `onclick` плашки по `и.магазин`;
`шаг_словами`: `eshop_find`.
